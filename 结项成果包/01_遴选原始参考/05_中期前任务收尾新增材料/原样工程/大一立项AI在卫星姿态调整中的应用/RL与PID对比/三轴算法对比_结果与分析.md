# 三轴姿态控制：PPO / SAC / TD3 对比结果与分析

生成时间：2026-10-11
数据来源：`compare_rl_algorithms.py`（可复现，直接重跑即可重新生成 CSV 与图）
模型：三个算法各自的 **80 万步最终模型**（`ppo_satellite3d.zip` / `sac_satellite3d.zip` / `td3_satellite3d.zip`）

---

## 1. 实验设置

| 项目 | 设置 |
|---|---|
| 环境 | `三轴强化学习/satellite_env3d.py`（三轴统一，三个算法完全一致） |
| 观测 | 误差旋转向量 (3) + 角速度 (3) = 6 维 |
| 动作 | 三轴力矩 (3)，各轴 ∈ [−2, 2] N·m |
| 奖励 | `−(1.0·‖e‖² + 0.1·‖ω‖² + 0.001·‖τ‖²)`，稳定（‖e‖<0.02 rad 且 ‖ω‖<0.02 rad/s）额外 +1 |
| 动力学 | ω̇ = I⁻¹(τ − ω×Iω)，dq/dt = 0.5·q⊗(0,ω)，I = diag(1.2, 1.0, 0.8)，dt = 0.01 s |
| 训练预算 | 各 80 万步（**同预算对比，不挑 checkpoint**） |
| 评测 | 29 个初始姿态（roll/pitch/yaw 各 0–90° 步长 15°，三轴对称 0–60°，三轴耦合 3 个），**无干扰**干净对比 |
| 单次仿真上限 | 20 s（2000 步 @ dt=0.01） |
| 阈值 | 1.0° |

**两个指标的口径（重要）**

- **纠正时间**：误差进入 1° 以内、且此后**不再超过** 1° 的时刻。20 s 内未做到则记"未稳定"。
  汇总时**只统计初始误差 > 1° 的姿态**——初始就在阈值内的姿态（如 0°,0°,0°）本身
  就算"稳定"，把它们平均进去会把均值稀释成虚低的值。
- **末段平均误差**：轨迹**最后 0.5 s** 的 |误差| 平均值。
  这里**没有**沿用 `metrics.steady_state_error`：它取"最后一次超过阈值之后"的均值，
  对**持续振荡、始终不收敛**的策略会退化成只剩 1 个采样点的平均，数值虚低、看起来
  反而比收敛的策略更好。末段均值对收敛与不收敛的策略都适用，是可比的。

## 3. 原因分析

### 3.1 首先是一个真实的环境 bug（已修复）

环境 `satellite_env3d.py` 的 `_quat_error()` 最初**漏掉了四元数的双重覆盖处理**：

四元数里 `q` 与 `−q` 表示**同一个姿态**。若 `q_err[0] < 0` 而不翻符号，得到的误差角会
跑到 [π, 2π] 区间、且**旋转轴方向相反**——即"绕远路"的解。这会让 agent 被引向**相反方向**。

修复后实测：270° → 90°，359° → 1°，181° → 179°（均取最短路径），正确。

**影响范围**：

- 该 bug 只在误差超过 180° 时才触发。
- **PPO 的既有结果完全不受影响**——修复前后逐用例对比，PPO 的最终误差**逐位相同**
  （2.49 s / 0.771°，各用例 0.70 / 0.49 / 0.76 / 0.68 / 0.44），说明 PPO 的轨迹从未
  进入过 >180° 的区域。因此 README 中已有的 PPO 单轴 / 三轴 / RL-vs-PID 结论**全部仍然有效**。
- **SAC / TD3 受影响严重**：离策略算法的探索会到处乱走，轻易进入 >180° 的区域，
  于是从"方向完全反了"的观测里学习。这解释了它们最初**卡死在固定值**（SAC 恒定 2.99°、
  TD3 恒定 9.585°，与初始姿态无关）的怪异现象。

> 同一个 bug 也存在于原始 PID 代码 `pid/three_axis/quaternion_utils.py:92`（RL 环境从此移植）。
> 由于 PID 控制器的指令误差通常很小，实际未触发，但它是一个**应当修复的隐患**。

### 3.2 SAC 为什么停在 ~2.7° 而不是收敛

修复环境、并用真实指标（每 2.5 万步评测 3 个固定姿态，见 `训练收敛监控.txt`）监控后：

- SAC 从 17.8° 一路降到 ~2.7°，**随后就卡住了**：70 万步后甚至回升到 3.2°。
- 全程在 2.1–3.6° 之间来回，**不是噪声抖动，而是一个稳定的局部最优 / 极限环**。

直接原因：**熵系数塌缩**。SB3 默认 `ent_coef="auto"`，在本任务上自动熵系数会迅速掉到
~4e-4，探索过早消失，策略停在"转了一部分但没转到"的解上。改用固定 `ent_coef=0.05`
（`sac_*_N1` 配置）后，SAC 确实动了起来、也确实在下降，但**平台仍然存在**——说明
除探索之外，SAC 在此奖励上的收敛点本身就偏浅。

### 3.3 TD3 为什么完全学不会

TD3 最初**根本没有探索**：SB3 的 TD3 策略是**确定性的**，必须显式传入 `action_noise`，
而旧脚本漏了这一项。补上 `NormalActionNoise(σ=0.2)` 后 TD3 才开始下降（40° → 5°），
但随即**陷入剧烈振荡**：全程在 4–24° 之间乱跳，**没有任何收敛趋势**，80 万步的最终模型
（14.19°）反而比 60 万步的（7.97°）更差。

**一条尚未验证的猜想**（写在这里是为了诚实，不是为了下结论）：
完成姿态机动所需的力矩量级约 **0.01 N·m**，而探索噪声 σ = 0.2 N·m，是前者的 **20 倍**。
噪声可能一直在把策略从已找到的好解上踢开，导致价值函数永远追不上。要验证需要做
σ 的扫描实验（如 0.01 / 0.05 / 0.1），**本次没有做，所以这只是假设**。

### 3.4 为什么 PPO 反而最好

- **同策略（on-policy）**：PPO 只用当前策略采集的数据，一旦策略变好，坏数据立刻被丢弃，
  不会被 replay buffer 里的陈旧/错误经验长期污染——这正是 SAC/TD3 受害的地方。
- **随机策略天然带探索**：不需要额外的探索噪声机制，也就没有 TD3 那种"噪声过大踢翻好解"
  的风险。
- **本任务回合短、状态维度低**（6 维观测、3 维动作、500 步回合），正是 PPO 擅长的规模；
  SAC/TD3 的样本效率优势在这么小的任务上体现不出来。

## 4. 局限与后续可做

1. **TD3 的探索噪声未做参数扫描**——上面 3.3 的猜想是可验证的，值得补一个 σ 扫描实验。
2. **SAC 的平台**未彻底解决——可尝试更大的 `learning_starts`、更慢的 `tau`、更长训练，
   或改成"先模仿 PPO 再微调"的路子。
3. **本次对比是最终模型的同预算对比**，没有挑选最优 checkpoint（SAC 的 70 万步、
   TD3 的 60 万步都更好）。这样做是为了避免"挑樱桃"，但也意味着表格里的 SAC/TD3 数字
   是它们**最差**的一面。若要展示各自最好水平，需另附 checkpoint 扫描结果。
4. 三个算法都**没有在强干扰下评测**——鲁棒性对比见 `compare_robustness.csv`（仅 PPO）。
