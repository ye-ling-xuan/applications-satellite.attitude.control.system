# 一个月收尾与结项交付清单

本清单以已经扩充的单轴、三轴 PID/PPO/SAC/TD3 成果包为基础。未来四周的重点是团队理解与独立复现、完成原立项承诺的两篇学习综述、按学校格式提交报告和答辩材料。技术主线已经包含多算法对比、同模型部署校准与历史策略独立复测；学校“优秀”评定仍由评审决定。

## 版本与报告口径

| 版本 | 研究范围 | 可核对入口 | 使用约定 |
|---|---|---|---|
| V1：原结项主线 | 单轴 PID、普通 PPO、域随机化 PPO；独立三轴 PID 开发演示 | [V1 技术报告](结项技术报告.md)、[V1 三轴演示](../05_三轴拓展演示/README.md) | 保留原模型、数据与方法，作为前一阶段工作；不覆盖或拼接为 V2 算法排名 |
| V2：新增材料融合 | 单轴与三轴 PID/PPO/SAC/TD3 同条件对比，原始/整定/改进 PID，同 checkpoint 的 RL 零动作校准 | [V2 成果入口](../07_单轴三轴多算法对比/README.md)、[实验约定](../07_单轴三轴多算法对比/实验约定.md) | 作为当前答辩技术主线；最终数字引用该入口保存的正式结果 |
| 历史来源与迁移复测 | 新增材料 4 份历史策略在统一部署环境下复测 | [新增材料存档与审查](../01_遴选原始参考/05_中期前任务收尾新增材料/README.md) | 与新训练模型分开报告；执行器、时步和积分器变化须说明，不能称为原实验逐数值复现 |

V2 同一轴下各控制器共享动力学、可见观测、执行器约束、初态、扰动和噪声实现。测试配置为每轴 20 组初态 × 9 工况，初态在工况间复用；不能描述成每轴 180 个独立初态。三种 RL 每轴保留 11、22、33 三个训练种子，18 份新模型已经训练并保存；原策略及同模型校准版本全部保留，改善与退化都进入正式统计。各项实际结果、校准效果和失败情况以 V2 入口中的报告与 CSV 为准。

上述六个 PPO 的预算说明属于 **V1**：每种训练方式使用种子 11、22、33，各请求 1,000,000 交互步、实际训练 1,001,472 步，验证间隔 50,000 步。旧 `正式训练` 目录为 20 万步探索记录，`nominal/seed_11` 为中断联调记录，两者不纳入正式统计。**V2** 的 18 个模型使用新的统一算法训练协议，逐模型预算、实际步数、梯度更新次数、种子、源码与模型哈希以其 `training_metadata.json` 为准；相同交互预算不等于相同计算量。

软件已经可运行并有实测数据，但团队提交的学校格式报告、经文献核实的学习综述、PPT、实际分工记录和答辩准备仍需完成。生成的说明与技术报告应由成员逐条理解、核对并整理为团队自己的正式材料。

## 二、四周必做计划

每周指定一位收尾负责人，各成员交叉检查。以下日期按实际开始时间顺延；若学校截止时间提前，优先保证必交材料与核验。

### 第 1 周：全员理解与独立复现

**目标：成员能够亲自运行成果包，并解释主要方法、数据来源和局限。**

- [ ] 核对学校结项通知，记录截止日期、模板、附件、页数、签字及文件命名要求。
- [ ] 全员阅读成果包 README、工作总说明、V1 技术报告、V2 实验约定及融合分析；共同画出“模型—控制器—训练/验证—独立测试—指标—报告”的流程，并明确两版对应的数据。
- [ ] 在成果包根目录运行 `python run.py check` 和 `python run_multi.py check`；保存环境版本、命令、输出和运行日期。
- [ ] 至少由一位未参与代码整理的成员，独立重新评估 V2 已交付模型，输出到新目录；绘图后与正式 CSV 逐项核对。建议使用 `python run_multi.py evaluate --output "07_单轴三轴多算法对比/团队独立复现/results"`，再对同路径执行 `plot --results` 和 `report --results`，避免覆盖正式结果。
- [ ] 运行三轴演示；若做回归核验，按三轴 README 使用 `--check`。
- [ ] 每位成员讲解至少一项核心内容：动力学/四元数、PID/抗饱和与滤波、PPO/SAC/TD3 的采样和探索差别、零动作校准/指标与配对数据。成员之间互相提问并记录尚未理解的问题。
- [ ] 固定正式报告采用的基线版本、模型、数据和图表；后续实验均另设目录。

**本周交付：**团队复现记录、环境与命令记录、问题清单、学校提交要求清单、职责表。复现发生差异时先检查依赖版本、模型来源、随机种子和配置，说明原因；不为追求一致而手工修改结果。

**验收：**另一位成员可以只依照 README 完成检查与评估；每位成员能解释一张核心图的实验条件、指标含义和实际结论。优先评估现有模型即可，无需为了形式而重复全部训练。

### 第 2 周：完成两篇学习综述与原立项承诺核对

**目标：把学习积累整理成有来源、有理解、有本项目实例的正式文字。**

- [ ] 阅读 `01_遴选原始参考` 中的大一立项报告和中期检查报告，逐条列出承诺、当前证据和剩余工作。排除大创计划书作为依据。
- [ ] 完成“卫星姿态系统搭建学习综述”：姿态表示、单轴与三轴动力学、数值积分、PID、现实因素扩展及实现经验，结合本项目代码和曲线说明。
- [ ] 完成“卫星智能姿态控制系统学习综述”：强化学习基础、Gym 环境、PPO/SAC/TD3、奖励设计、探索与经验回放、训练与验证选择、域随机化和部署校准，结合两轴实测讨论适用范围。
- [ ] 核实每条引用的作者、标题、年份、出处和链接/DOI；阅读被引用内容，确认其支持正文论述。公式、图片、算法介绍及他人成果注明来源。
- [ ] 由另一位成员交叉审阅两篇综述，检查术语、单位、公式、图表说明和引用。
- [ ] 在“原立项承诺核对表”中明确哪些已经完成，哪些调整了范围，哪些仍未完成，并说明理由。

**本周交付：**两篇可独立阅读的学习综述、参考文献表、原立项承诺核对表。名称和独立提交形式最终按原立项报告与学校要求确定，不能仅用代码目录或技术报告替代原承诺。

**验收：**每篇都能区分文献知识、本项目实现和本项目实测结论；综述作者能解释关键公式和方法。历史 DDPG 脚本仍不等于完成 DDPG 实验；三轴多算法统计依据 V2 正式数据，V1 单场景演示只证明该开发场景的实现。历史 README 中的优胜结论必须与新的持续保持判据区分。

### 第 3 周：学校格式结项报告、PPT与分工记录

**目标：把研究问题、方法、证据和成员工作组织成完整的提交材料。**

- [ ] 邀请指导教师审阅目标完成情况、科学表述和学校提交材料，落实反馈并保留修改记录。

**本周交付：**学校格式报告初稿、PPT初稿、成员贡献说明、附件目录及指导教师反馈记录。

## 三、可选技术突破：最多选一项

只有在第 1 周复现已完成、第 2 周必做材料进展正常，且有成员能独立负责时启动。可从以下两个方向中选择一个；时间不足时直接取消，不影响已有软件成果的结项整理。

| 二选一方向 | 具体任务 | 最小验收证据 |
|---|---|---|
| 积分或历史观测实验 | 增加可解释的误差积分或固定历史观测，明确其尺度、复位、限幅和观测维度；向被比较控制器提供匹配的测量历史/信息条件，讨论 PID 内部积分与 PPO 观测的区别 | 预先确定新训练、验证和独立测试场景；保存多个训练种子的模型与结果；比较精度、成功率和控制代价，报告无提升或退化 |
| 时延实验 | 明确测量时延或动作时延的含义，用固定队列与一致初始化实现；所有被比较控制器采用相同时延条件，限定少量时延等级 | 记录时延定义、步数、缓冲区行为和配置；区分已有模型的零样本压力测试与重新训练模型的适应效果；给出配对统计与失败案例 |

新增实验统一保存到新的模型/数据目录，不能覆盖 `正式训练_100万步`、本次正式基线数据或已交付图表。新模型严格区分训练集、验证集和最终测试集；用验证集决定参数与检查点，最终测试集不得用于选模。旧版与新版环境不混用模型，正式报告同时保留原基线与新增实验的版本说明。

新增工作从小规模调试和实现核验开始，有稳定证据后再训练。当前已经有单轴、三轴的 PPO/SAC/TD3 及部署校准证据管线，本月优先完成复现与正式材料；继续加算法须有明确问题，不能只追求算法数量。若新方案没有取得改善，也保留结果并分析原因。

## 四、未来研究：本月结项非必做

单轴与三轴的 PPO/SAC/TD3 比较和同模型部署校准已纳入 **V2 已实现主线**，不再列为未开展任务。尚未开展的 DDPG 完整实验、模型辨识与 MPC、STK 联合验证、真实执行器能耗模型、硬件在环和在轨工程化，可作为后续方向。若原立项明确承诺其中某项，应在承诺核对表中如实说明范围调整或未完成状态。
