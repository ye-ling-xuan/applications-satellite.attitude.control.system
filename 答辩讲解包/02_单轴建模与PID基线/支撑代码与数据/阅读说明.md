# 本步支撑材料怎么读

优先看参数与结果，再看实现。所有“复制”文件都在[来源清单](来源清单.json)登记并与原件逐字节核对。

| 位置 | 建议查看内容 |
|---|---|
| [pid_best.json](PID整定/pid_best.json) | 最终Kp、Ki、Kd与验证集来源 |
| [pid_search_validation.csv](PID整定/pid_search_validation.csv) | 全部120组候选，避免只看到最终参数 |
| [pid_validation_scenarios.json](PID整定/pid_validation_scenarios.json) | 10个验证场景 |
| [summary.csv](统计证据/summary.csv) | 三种控制器的48组原始汇总；本步读PID行 |
| [result_verification.json](统计证据/result_verification.json) | 既有5600回合独立核验记录，不代表本次重新跑全量实验 |
| [config.py](代码/satellite_benchmark/config.py) | 物理、奖励与验收参数 |
| [env.py](代码/satellite_benchmark/env.py) | 动力学和动作到力矩的映射 |
| [controllers.py](代码/satellite_benchmark/controllers.py) | PID、限幅和抗积分饱和 |
| [metrics.py](代码/satellite_benchmark/metrics.py) | “持续停稳”的实际判定 |
| [evaluation.py](代码/satellite_benchmark/evaluation.py) | 验证场景、参数搜索、配对评估和汇总 |

`代码/satellite_benchmark`保留完整8文件V1模块，避免拆散内部相对导入。依赖版本见[requirements-tested.txt](代码/requirements-tested.txt)。这些是支撑实现副本，不是复制全部成果包的启动入口；不要在这里运行源成果包的默认全流程命令。

`固定轨迹`保存`test_00_000`和`test_00_001`两条PID轨迹，初态分别为−45°/−3°每秒、45°/3°每秒。两者是固定对称演示，不代表两次独立训练或总体统计。

外层“核心图_PID固定响应.png”由[生成PID固定响应图.py](生成PID固定响应图.py)从已复制的正45°轨迹绘出，无新训练或仿真。运行此绘图脚本会更新本步骤外层图，不修改源成果包。

`.npz`可以用`numpy.load(path, allow_pickle=False)`读取；`metadata_json`中包含原始场景与指标。模型训练时的源码哈希与归档时源码差异保留在核验记录中，不能把后续维护过的绘图/日志工具冒充训练当时版本。
